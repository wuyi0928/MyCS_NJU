# 多人共享记账系统：当前设计说明

本文件是实验二设计材料，汇总实验一访谈修订版及本会话用户逐项审查后的现行方案，不是实验报告。正文只描述当前规则，修改历史保留在独立人工审查记录中。用户作出判断、AI执行绘图和整理，不将AI操作描述为用户手工绘图。

## 1. 材料范围

项目为多人共享记账系统，账本示例名称“呢喃小屋”。第13张首页标题“哈记米”、标语“不烧心的流水生活”、左下卡片标题“画账为牢”；其他页面标题保持“共账”。

7张UML覆盖5种类型：类图、组件图、状态图、时序图、用例图；每图含PlantUML源码、PNG和SVG。类图必画，另有组件图，并覆盖行为性与交互性图。

15张静态UI，每张含PNG及可编辑SVG，画布1440×1000。黑、银灰、青绿色配色，进度交界用20/24px小轮胎，产品界面无轮胎图例；按钮和标签居中。SVG尚未在Figma/Pixso中导入编辑验证，HTML是图片浏览目录，不是可运行系统。移动端未设计。

## 2. 现行规则

### 2.1 角色和权限

保留管理员、普通记账成员、只读成员。创建者为管理员，邀请加入的新成员默认管理员；允许多管理员，并可调整为普通或只读角色，不能取消最后一名管理员。管理员均拥有记账、审核他人、预算、成员权限、结算、日志与导出等全部管理权限。

管理员与普通成员可新增本人收支，维护本人允许状态的未审记录。管理员不能借管理身份直接覆盖他人未审输入。只读仅查看，无记账、审核、设置及导出权限。每次请求校验当前成员、角色、账本和对象归属；越权403且数据不变。

管理员禁止审核本人创建的收支及调整，通过、驳回均适用，按创建人而非付款人判断。单管理员可提交，记录保持待审，需邀请另一管理员审核，无自审例外。

邀请24小时有效，重复加入不产生重复有效成员关系。退出后不能访问但历史保留；管理员按既有要求先转让，不能失去最后管理员。不增加有欠款禁止退出规则。

### 2.2 金额、分配和状态

普通收支金额大于0、最多两位小数、最高1000000.00元（含边界），存整数分。收入和支出都支持均摊与手动指定金额。

均摊先给每人M//n分，余下M%n分随机分给不同成员，每人额外1分。明细提交时保存；刷新、重试、审核和结算不重新抽签。手动分配非负、成员不重复、合计等于总额，允许个别成员为0分；收入用同一方式分配受益金额。

主状态为待审核、已驳回、已撤回、已审核、已作废。本人可修改待审或驳回记录，待审可撤回，驳回/撤回后可修改重提。其他管理员通过或驳回。已审原金额不能覆盖；结算前整笔无效可填原因作废，已作废为终态。已更正与结算锁定是附加标记，不新增主状态。

### 2.3 预算和待审名额

支持月总与分类预算，占用包括有效已审核支出和待审核支出。收入不抵减支出预算。超预算只提示，仍可提交，由其他管理员审核；取消旧设计的超预算阻止开关。

每人每账本同时最多5笔待审，管理员同样适用。达到上限先处理或撤回，再新增或重提。审核通过、驳回、撤回释放名额；就地修改一笔待审不增笔数，重试不重复占位。收入、支出、调整统一计数是AI防绕过实现建议。

待审通过转已审时预算不重复增加；驳回/撤回释放占用，待审修改按新旧金额差更新。待审补记和冲减的细化见第7节，不把未通过退款当作已确认可用额度。

### 2.4 更正和月份

原金额和已审核主状态保留，允许多次独立关联调整，均由其他管理员审核。有效金额=原金额+各笔有效已审核调整的有向效果；待审、驳回、撤回、作废调整不进入有效财务统计。

跨月调整计入当前月，不回写原月及旧快照。本版按提交时当前月固化归属、跨月审核不自动迁移，是实现细化；补记/冲减与正金额分开存储也是实现建议。

### 2.5 结算和保护

所选月份待审核收入、支出、调整全部处理完，才可新生成月结单。处理完不等于全部通过：驳回和撤回不计有效收支，也不再阻止；重提回待审则再次阻止。其他月份待审不影响本月。

同账本同月至多一张有效单；结算保存记录版本、分配和成员净额快照，相关日志、锁定整体保存或回滚。结算不是新收支，不清零历史统计，无逐人收付确认或真实支付功能。

管理员可填原因作废错误结算单，旧单与快照保留，重结创建新单。曾成功结算的原记录持续锁定，结算单作废也不能直接改、撤、废，只能关联调整。跨月调整保留其归属月，不因原月重结回搬或重复累计。

### 2.6 查询、日志和导出

类别、成员、时间、金额、状态及备注关键词可组合查询；提供分类、成员、月度统计。有效统计只含有效已审收支和调整，与预算含待审的口径区分。

关键变更记录账本、对象、操作者、时间、动作和结果；成功日志与业务同事务。管理员可查日志、导出统计及日志，普通和只读不可导出。日志至少1年且至少至课程结束，取较晚者；无业务删除入口，不记录密码或会话凭据。

## 3. 模块和存储设计

采用模块化单体分层方案：界面→统一授权入口→业务模块→数据访问层→关系数据库。不要求微服务，具体数据库产品后续确定。

| 模块 | 职责及依赖 |
|---|---|
| 账本成员 | 创建、邀请、角色及退出，保留历史关联 |
| 收支审核 | 录入、本人维护、撤回重提、他人审核、作废及更正，集中控制状态版本 |
| 分配策略 | 均摊/手动、随机余分固化、收入受益和调整有向效果 |
| 预算 | 已审及待审占用，总/分类预算和超额提示，无超预算拒绝开关 |
| 查询统计 | 有效口径、多条件筛选、分类成员月度统计 |
| 结算 | 待审清空检查、唯一有效单、快照、历史锁定及作废重结 |
| 日志导出 | 成功日志追加、管理员查导、保留控制 |
| 事务幂等 | 请求去重、版本校验、5笔名额并发控制及回滚 |

数据流：授权→金额及分配校验→幂等及名额检查→保存待审与分配、占用预算→其他管理员审核→有效统计→当月待审清空→月结快照锁定。超预算只提示，不改变这条审核流程。

金额整数分，密码加盐哈希，所有子数据带账本及主对象关联。预算总作用域和分类作用域分别保证唯一，避免NULL唯一性语义造成重复总预算。

账本+请求号唯一，保存摘要和首次结果，先授权后返回旧结果；同号不同内容拒绝。业务、分配、成功日志及凭据同事务；失败回滚可原号重试，保留期限仍未定。

账本+创建人配额协调防止并发突破5笔。影响月份集合的提交、重提、审核、撤回、作废、调整和结算遵守相同月份协调协议；同一事务检查待审、读取一致集合、写入快照。数据库有效单唯一约束兜底，跨月锁按固定顺序获取。

历史快照复制版本、金额、分配和净额，历史展示读快照，不读当前数据重算。锁定检查成功结算的历史关联，不仅看当前有效单；失败回滚不留下锁定。作废和重结分别事务化，新单失败不自动恢复旧单。

## 5. 示例时间线及金额

页面按功能编号，不是同一时刻截图。以下时间线区分结算前与结算后，纯为设计示例，不声称真实用户操作已经发生。

**10月结算前（01～04、06、07）：** 已审支出为小林生活300、小周房租960，已审收入为小陈实收600。有效支出1260、收入600、结余-660。待审晚餐120和清洁用品80不计财务统计，驳回交通费25也不计入。预算含待审为1460/2000，73%，剩余540；居住960/1000、生活380/500、餐饮120/500。01提示先清待审，02原账未显示已结算。

**10月结算后（09及12）：** 示例中两笔待审在结算前撤回，因此快照仍为有效支出1260、收入600。三人各承担支出420、收入受益200。净额=实付支出−承担支出−实收收入+受益收入：小林+80、小周+740、小陈−820，合计0，正数应收、负数应付。结算不改变历史有效汇总。

**11月更正（05、08）：** 对10月原账300提交待审冲减20，另一补记10已撤回，当前关联有效额仍300，本次通过后280。10月统计和快照不回写，冲减通过后归11月。11月有1笔待审调整，不能生成新单。

页面03的120三人各40；06的分类占比是有效支出构成，不是预算使用率，轮胎只按该条比例显示；07才是预算占用。各分配均可复算，随机余分不会使已有快照变化。

## 7. 尚未确定的边界

1. 只读与退出成员是否参与新分摊，退出成员未结金额后续处理。
2. 已结算月份是否可补录，重结涉及后续跨期结算时如何处理依赖。
3. 未结算但多次更正的记录整笔作废时原账与调整如何联动；累计冲减是否可超过原账有效额。
4. 驳回原因是否必填，管理员转让是否需接收方确认。
5. 登录注册、名称限制、查询时间边界、分页、导出格式、性能测试负载。REQ-023初稿易用性指标不属于已确认要求。

实现建议而非用户逐字确认：调整提交月固定归属；5笔名额统一计收入/支出/调整；待审补记增加预算占用，待审冲减暂不释放，以免未审核退款扩大额度；金额或分配依据改变后重提才重新抽签。上述建议可后续审查，不伪装成已确定需求。
